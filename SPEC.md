SF Live Suite — Spec v2
Nov 3, 2026 · Wiley
Source of truth. Decisions are dated inline. Builds are tested as whole suites only.

# Purpose

A suite of Ableton Live plugins (AU + VST3, macOS, Apple Silicon) for performing hypnotic / dub techno live: very simple note content (often one note, fixed patterns), with all variation played on knobs. Designed from the start for a fixed live rig: one Live set that never changes, songs switched by preset, the OXI One MkII sequencing, the OXI E16 knob array (absolute 0-127 CC with value feedback) playing.

The releases are live sets, not tracks [Nov 3]: sets are recorded as played and released, from a bedroom session to a festival main stage. So the bar is release-grade sound from every plugin at 44.1 / 48 / 96 kHz and any buffer size, and nothing a performer does with a knob may produce a click, an alias, an inter-sample over, a level jump or a dropout. See Sound quality.

# Standards

## Visual
Black, white and greys. Colour only carries information:
- RED: clip / fault / missing file
- AMBER: conflict / warning / armed-but-waiting states that need attention
- GREEN: active / locked to the grid / source connected
- CYAN: the value of the control being touched

Monospace type, 1 px rules, no decoration, no gradients, no shadows.

## Naming
Boring, practical, uppercase. Plugins appear in Live as `SF <ROLE>`. Parameters are plain words (`DENSITY`, `GATE`, `CUTOFF`, `DEPTH`). Models are descriptive (`KICK 909-TYPE`, `ACID 303-TYPE`, `STAB DUB`). Trademarked machine names appear only as "-TYPE" descriptions. Presets are `GROUP/NAME` in the same plain words (`DUB/CHORD 1`, `ACID/SQUELCH`); no artist names, no trademarks.

## Controls
- The first 8 parameters of every plugin are its performance row (Live's device view, one E16 row). Everything else is set-and-forget.
- Every knob is smoothed (30 ms) so 7-bit CC never steps audibly; ranges and curves are tuned so the whole travel is usable.
- Standard trio wherever it applies: DENSITY (how many events), GATE (how long each lasts), FILTER (bipolar DJ filter: left low-pass, centre open, right high-pass).
- System controls on every plugin (appended, never in the first 8):
  - SLOW: CONTROL / 1-64 BAR / OFF. Every performance-row knob travels to where it is set over exactly that many bars, however far it moved (with SLOW at 32 BAR a quarter turn becomes a 32-bar rise). Song recalls glide the same way. MACRO moves stay immediate. The knob shows "GLIDE now>target" in green while travelling. [decided Nov 2: fixed time, performance row only]
    CONTROL (the default; it was OFF, at the same index, so older sets sound the same while SLOW ALL is OFF) takes the length from SF CONTROL's SLOW ALL (OFF / 1-64 BAR), one knob for the whole set, honoured only while CONTROL runs. A length or OFF (appended, so saved lengths keep their index) is the plugin's own and wins over SLOW ALL. The length is fixed when the move is made (a turn, automation, a recall): changing SLOW or SLOW ALL never touches a knob already travelling, it only sets how the next moves go; a knob moved again while travelling sets off from where it got to. [decided Nov 3: SLOW ALL, so a move can be a glide or direct without opening a plugin]
  - MACRO SRC (OFF, MACRO 1-6) and MACRO AMT (-100..+100 %): the plugin follows one of SF CONTROL's six macros. Each module decides which knobs respond and in which direction.
  - MOTION [added Nov 3]: two modulators, M1 and M2, each SOURCE / RATE / TARGET / DEPTH. See MOTION below.
- PRESET menu in every header [added Nov 3]: factory presets (191 across 26 plugins) and user presets. See Presets below.
- Nothing can hurt the PA: resonance is level-compensated (and a resonance guard rides peaks above 0.9 down with a smooth gain, never a waveshaper), feedback above 100 % saturates instead of exploding, every output is clamped at +12 dBFS. NaN/Inf, or 250 ms held at the clamp (a runaway), replaces the output with silence and resets the module; the header's meter label shows FAULT in red. PANIC on SF CONTROL silences every SF plugin (see Engine).

## Live / controller workflow (decided Nov 2)
- E16 is mapped with Live's MIDI Map (Cmd-M) with Remote on for its output, so knob rings follow song and value changes. The plugins report every recalled value back to Live.
- Song change: Program Change on MIDI channel 16 into SF CONTROL (channel selectable). Recall lands on the next bar line while Live plays, at once when stopped. VST3: SF CONTROL exposes 16 programs (SONG 01-16); Live 12.2 and later deliver MIDI Program Change to VST3 plugins as a program change (12.2b10 release notes), earlier versions don't; the AU reads Program Change from MIDI in any version. [decided Nov 2, updated Nov 3; needs Live test]
- Stems from Live's own stem separation go on their own tracks; SF TAP on each puts them into Pocket and ALLOC.

# Sound quality [decided Nov 3]
Nothing audible may come from the implementation. Measured by SFTests (`--quality`), every build.
- Oversampling: every nonlinearity runs oversampled.
  - Polyphase IIR halfbands (elliptic, HIIR-style design, cascaded for 4x): flat to 20 kHz within 0.0001 dB, image and alias rejection 118 dB at 44.1 kHz, 112 dB at 48 kHz, 123 dB at 96 kHz. Near-zero latency, so it is used inside voices and feedback loops.
  - Linear-phase FIR (79- and 23-tap halfbands, then a Kaiser low-pass decimator, 100 dB) where phase matters: SF LIMIT's clipper. 99.5 dB rejection.
  - Rates: synth voices 2x (ladder, MS20-TYPE and SYNC models 4x); KICK, PERC 2x; DRIVE and STRIP drive 4x (DRIVE moved from JUCE's oversampler, about 70 dB, to the suite's own); FILTER, ENERGY, VOICE drive 2x; DELAY loop saturation 2x; RUMBLE grit 2x; LOWEND sub clip 2x; STRIKE fracture 2x; TONE 2x; LIMIT clip 4x linear phase.
  - Oversampled stages are never switched in and out (that would move their delay and click): they run all the time, and each drive fades in from exactly clean at 0 (FILTER, ENERGY, STRIP across the whole knob; synth DRIVE over the first 10 %; VOICE DRIVE and RUMBLE GRIT over the first 2 %, so their calibrated defaults are unchanged). [review, Nov 3]
  - LIMIT's FIR stages are sized from the sample rate (2x stage 151 taps below 46 kHz, 79 above; 4x stage 31 taps): the whole path is flat to 20 kHz within 0.01 dB at 44.1, 48 and 96 kHz.
- Oscillators: phases wrap for any increment and partials above 0.45 x the voice rate go silent (TUNE +24 on note 127 used to read past the end of a table) [Nov 3, second audit]; band-limited wavetables (one table per octave, harmonics kept below 0.75 x the oversampled Nyquist, 4-point Hermite reads), hard sync with BLEP correction, polyBLEP carriers in VOICE, first-order anti-derivative anti-aliasing (ADAA) on tanh stages. Alias floor, worst case across a 3-octave sweep: ACID 303-TYPE 94 dB, FM 97 dB, STRING MACHINE 105 dB, SUB OSC 94 dB, MS20-TYPE 77 dB, SYNC 79 dB.
- Samples: files are converted to the session rate with a windowed-sinc resampler on load. Playback reads at or below the original rate with 4-point Hermite; read faster (transposed up), it uses a Kaiser-windowed sinc low-pass at 0.9 / rate, so nothing folds back (a 17 kHz sample an octave up used to alias to 14 kHz at full level; now -107 dB). Above twice the original rate it reads an octave-down copy made at load (half-band filtered, flat to 0.43 of the band, 90 dB down from 0.58) where the rate is between 1 and 2, so the cost stays at most about 36 taps however far up a sample is played (the plain reader costs about 18 x rate taps). Every sampler and DECK's varispeed share the reader. [octave-down copies: Nov 3, second review] Floating-point files that peak above full scale are stored scaled with their gain, and reopen unchanged. [Nov 3, second audit]
- Engine: audio runs in 64-sample chunks on a fixed grid of the stream (see Engine), so the output does not depend on Live's buffer size.
- SF LIMIT: see Master / mix. True peak at the output never exceeds CEILING (8x detection, measured on dense clipped material, sine sweeps and square waves).
- Loudness metering (LIMIT, DECK analysis): ITU-R BS.1770-4 / EBU R128. K-weighting designed exactly at any sample rate; momentary 400 ms, short-term 3 s, integrated with absolute (-70 LUFS) and relative (-10 LU) gating on a 0.1 dB histogram (constant memory over a whole set). Reads -20.00 LUFS on the 1 kHz reference sine.
- REVERB: feedback delay network with input diffusion (four all-passes per channel) and two-band absorption in every line (shelving: DARK shortens the highs while the lows keep DECAY). RT60 of the lows at DECAY 1 / 3 / 8 s: 0.99 / 3.04 / 8.00 s. Line lengths, loop gains, absorption and modulation depth ramp across each chunk and glide (30 ms), so SIZE / DECAY / DARK / MOD under a knob, automation, MACRO or MOTION never zipper. Reverbs inside ENERGY and STRIP ring out after their send closes instead of being cut.
- DELAY: TONE and saturation sit inside the feedback loop, so each repeat is darker (or thinner) and dirtier than the last. FREEZE crossfades (10 ms) into a lossless loop (feedback 1, no filtering, the wow stops, the head reads whole samples once it has settled; TIME turned while frozen reads between samples until it settles, so it bends instead of zippering) [second review]. REVERB FREEZE fades the input into the frozen space over 10 ms (cutting it would circulate the cut for the whole hold) [second review].
- GLUE: 6 dB soft knee.

## Gain staging [decided Nov 3]
Every instrument model is trimmed so that at default settings it plays at its role's loudness target (integrated LUFS, role pattern): KICK -15, PERC -22, RUMBLE -20, BASS -18, LEAD -20, PAD -22, VOICE -20, STRIKE -20. Switching MODEL never jumps the level, and a rig at default LEVELs is balanced with headroom on the master before GLUE and LIMIT. Trims are in `Source/modules/Calibration.h`, applied after any drive, and verified by SFTests (`--calibration`). Sample models are not trimmed (the file's own level counts).

# Shared architecture

## SF BUS
One block of POSIX shared memory (`/sf_live_suite_bus_v7`) mapped by every SF plugin, across plugin binaries and processes. Lock-free atomics only. A segment of another version or layout (another build; the layout size is stored in the segment, since macOS rounds the segment size up to whole pages) is never mapped; that plugin falls back to a local bus, so all plugins in a set must come from the same build. Verified Nov 2: two separately built plugin binaries (SF KICK, SF DUCK) loaded in a VST3 host share the bus and Pocket works between them. Carries: macros, song select / store requests, PANIC, KEY, SLOW ALL, glide reports, kick reports, ALLOC source energies and cuts. v3 [Nov 3] added PANIC and KEY; v4 [Nov 3, second audit] added the recall bar line, held PANIC and source ids; v5 [Nov 3, third review] added SF BUILD's drop (bar line, depth, duck window, where and when it was planned), STORE TO's song, and where a song change was asked for. v6 [Nov 3] added SF CONTROL's SLOW ALL; v7 [Nov 4] the glide reports (GLIDE RINGS). If shared memory is unavailable the bus falls back to process-local (plugins in one process still talk); SF CONTROL shows BUS SHARED / LOCAL ONLY.

## Clock
Live's transport when playing. When stopped, a wall clock at the last tempo stands in, so tempo-synced motion keeps running and every SF plugin agrees on the beat.

## Engine [decided Nov 3]
- Every plugin processes in 64-sample chunks on a fixed grid of the audio stream, whatever Live's buffer size. Parameters (30 ms smoothing, SLOW glides), MACRO and MOTION update once per chunk at the same stream positions every time, and envelopes, modulators and Pocket run on that grid, so the output is the same at any buffer size: bit-identical at buffer sizes 1 to 2048 for every module (SFTests). MIDI events keep their exact sample offsets inside the chunk.
- Song recall lands on the exact sample of the bar line (the chunk is cut there), not on the next buffer. SF CONTROL decides the bar line once and sends it with the song (bus v4): every plugin lands on the same bar whatever order Live processes the tracks in (a plugin processed before CONTROL in that audio cycle sees the change a block later and catches up at once, on the same bar). A change requested within 30 ms after a bar line (a Program Change sent on the downbeat) belongs to that bar; later in the bar, to the next one. Positions are compared with a 0.001-sample tolerance, so rounding of the song position can never push a recall to the following bar. [Nov 3, second audit]
- After a recall the recalled values hold until Live reports them back; the moment the host's value moves away from what it was at the recall (the performer turns the knob, or automation), it has the parameter. STORE ALL in that window stores the recalled values. [Nov 3, second audit / second review] A value Live still disagrees with 3 s after it was told gives way; the 3 s start at the report, not the recall: Live's message thread can be busy for longer (saving the set), and the recall used to give way and the old song come back. [Nov 3, fourth review]
- The report to Live never overwrites a newer value: every change Live makes to a parameter (other than the plugin's own report) is counted, and a recalled value whose parameter has since moved away from its value at the recall is neither reported nor held. A knob turned (or a second recall) between the recall and the 30 Hz report used to be written back over with the first recall's value. Live echoing an old value doesn't count as a move. [Nov 3, third review]
- If the transport jumps back while a song waits for its bar line (an Arrangement loop wrapped, a relocate), that bar may never come: every plugin then recalls on its own next bar line, together, and if the transport jumps back again first (a loop with no bar line inside it) at that jump. A request made in the last block before a loop wraps reaches some plugins only after the wrap (SF CONTROL itself and the plugins Live processes before it); CONTROL sends where it was asked for, so such a plugin treats it as asked for before the jump, like the others, and a request asked for just after the wrap as a fresh one. The bar line counts as where the transport jumped from if it lies within a sample of it (a bar line between two samples can leave the loop's last block ending just past it). Before: such a request left CONTROL and the plugins before it waiting for good, and one asked for in the first block after a wrap landed a loop early in the plugins after CONTROL. [Nov 3, second review; wrap: third and fourth review]
- A song's KEY changes on the song's bar in every plugin: CONTROL sends the key with the song, and each plugin switches in its bar-line chunk, whichever side of CONTROL Live processes it on (KEY read once per block used to switch a block early or late). [Nov 3, second review]
- Safety: after every chunk, NaN/Inf become silence, the output is clamped at +12 dBFS, and NaN or 250 ms held at the clamp resets the module (FAULT, red, in the header).
- PANIC (SF CONTROL): every SF plugin fades out over 5 ms, then clears every voice, tail, delay line, envelope and filter state, and stays silent for as long as PANIC is held (effects take no input, instruments no new notes, DECK keeps its place in time); on release the input and the output both fade back in over 5 ms (so an effect with latency, DELAY's dry path or LIMIT, never plays a step). Use it for a runaway, a stuck note or a wrong song recall in front of a crowd. A second PANIC during the fade doesn't restart it. While it is held every SF plugin's header shows PANIC in red. Momentary buttons (PANIC, STORE ALL, THROW, RESET ...) never reopen pressed with a set, and a plugin window closed while one is held releases it, so PANIC can't be left latched. [held mute: Nov 3, second audit; release, latch: Nov 3, second review]
- No allocation, locks or file access on the audio thread. Samples are swapped through an atomic pointer; replaced samples are freed on the message thread after 2 s.

## Songs
Every plugin stores 16 song slots of its own parameter values (with the Live set). SF CONTROL selects the song (SONG knob/menu or Program Change); each plugin recalls its slot on the next bar. STORE ALL on SF CONTROL stores every plugin's current values into the selected song, or into the song STORE TO names (ACTIVE SONG = the selected song), which is not recalled: choosing a stored song on SONG first replaced the sound before it could be stored. The STORE TO song becomes the selected song (SONG follows, STORE TO goes back to ACTIVE SONG), unless a song change is under way: that change still lands and stays selected. SONG follows the bus (after a Program Change or STORE TO) only while the bus still has that song, and CONTROL never takes its own SONG update for a request: a Program Change right after STORE TO used to be overridden by it. STORE ALL goes out at the end of a host block in which no song recall landed: in such a block the plugins Live processes before CONTROL would store after the recall and those after it before (a mixed song, and with STORE ALL into the arriving song the plugins after CONTROL kept the old sound). STORE on any plugin stores just that plugin, into the selected song. [STORE TO: Nov 3, third review; the rest: fourth review] Empty slots leave the plugin as it is. Arrangement automation wins over recalled values (as on any device). SLOW applies to recalls, so a song change can glide. MOTION settings and SF CONTROL's KEY are part of songs.

## Presets [added Nov 3]
- The PRESET button in every header opens the menu: factory presets in GROUP submenus, user presets, SAVE USER PRESET, SHOW PRESET FOLDER. The button shows the loaded preset.
- A preset sets every sound parameter of the plugin (unnamed ones go to their defaults) and reports each change to Live, so the E16 rings follow. It never touches SLOW, MACRO SRC / AMT, ALLOC participation, ROLE, KICK BUS / MIDI sources, or venue data. Presets may set MOTION.
- 191 factory presets across 26 plugins (instruments, effects, master tools; none for DECK, CONTROL, ROOM EQ, ALLOC, TAP). Every one is rendered by SFTests: finite, in range, no runaway.
- User presets: one XML file per preset in `~/Music/SF Live Suite/Presets/<MODULE>/`. Copy the folder to move them between machines.

## MOTION [added Nov 3]
Two modulators in every plugin (M1, M2), stored with songs and presets.
- SOURCE: SINE, TRIANGLE, SQUARE, RANDOM (stepped), DRIFT (smooth random) are bipolar around the knob; RAMP UP / RAMP DOWN are one-way ramps that restart every RATE; KICK follows SF KICK's hits (RATE sets the release); NOTES (instruments: note velocity) or INPUT (effects: input level), RATE sets the release.
- RATE: 1/16 to 64 BAR, then (appended [Nov 4], so saved rates keep their index) 3/16, 5/16, 7/16, 1/4D, 1/2D, 1/4T, 1/2T, 3 BAR, 5 BAR, 7 BAR: cycles that run against the bar and meet it again every few bars (5/16 every 5, 7/16 every 7, the dotted values and 3 BAR every 3). All locked to Live's song position, so every plugin's modulators move together and move the same way every time the set is played. RANDOM and DRIFT are seeded per plugin instance; the seed is saved with the set.
- TARGET: any continuous parameter of the plugin. DEPTH: -100 to +100 % of the target's whole range, applied in the knob's own scale (a sweep of CUTOFF moves evenly in pitch, not in Hz). The modulation adds to the knob, MACRO and SLOW; the knob shows a bar for the modulated value.
- Steps (SQUARE, RANDOM, ramp resets, loop jumps) are slewed over 3 ms: no clicks.

## KEY [added Nov 3]
SF CONTROL's KEY (OFF, C ... B; stored per song) transposes the suite while SF CONTROL is running (the bus outlives sets, so a key left by a deleted CONTROL or another set is ignored). Parts are written in C; with KEY on, every pitched SF instrument plays them in the chosen key (nearest transposition, -6 to +5 semitones). KICK, RUMBLE and STRIKE snap their own pitch (the kick's fundamental, the rumble's thump, the object's main partial) to the nearest note of the key root, so the low end is always in tune with the track. KEY FOLLOW on each instrument opts out. OFF = no change anywhere.

## POCKET (kick-aware ducking)
SF KICK reports every hit to the bus: time (in beats), velocity, pitch sweep start/end and time constant, amplitude decay, and its FILTER corners. Any module with Pocket carves a kick-shaped hole in itself:
- DEPTH: how deep. SHAPE: one knob from transparent to pumping. Left: a narrow cut that follows the kick's pitch sweep down to its fundamental (felt, not heard). Middle: the low band (below ~3x the kick fundamental) ducks for the kick's length. Right: full-band pump, release tied to the tempo.
- Adapts to the kick: velocity scales each pocket (ghost kicks get shallow pockets), decay sets the length, the pitch sweep sets the frequencies, a high-passed kick closes the low pocket (the bass gets the sub), rolls merge into one dip on transparent settings and pump per hit on pumping settings.
- Safety: when kick tails overlap so much the pocket would be permanent, the pocket shrinks to the attack.
- Kick returns after a gap: pockets fade back in over a beat (breakdowns open up the bass automatically).
- Sidechain fallback (SF DUCK, SOURCE = SIDECHAIN, or any time no SF KICK is reporting): low-band envelope of the sidechain input.
- Transport jumps [decided Nov 2]: kick reports carry a wall-clock stamp; a report is used only if the wall time since it fits the musical time since it, so reports from before a loop wrap / restart / relocate are ignored. RUMBLE re-arms on a backward jump. POCKET OFFSET on SF CONTROL (+/-20 ms) calibrates Pocket and RUMBLE timing for the host if needed.
- Timing: Pocket runs 512 samples of lookahead (reported to Live as latency) so a kick report from the same audio cycle arrives before it is needed. Requires Live's buffer size <= 512. [decided Nov 2, needs Live test]
- After SF BUILD's drop [Nov 3, third review]: for DUCK TIME after the drop's bar line every Pocket stage also dips the whole band DROP DUCK dB under each kick, whatever its DEPTH (full for the first half of the window, easing out over the second; each dip follows the kick's own envelope, back within half a beat). Only the drop's own kicks count (from 10 ms before its bar line: MIDI timing), and the duck fades in over 5 ms from the bar line, so it never starts with a step (a roll into the drop used to start it at the depth the roll's last kick still had, a click on pads and bass). BUILD publishes the drop when DROP is pressed, before the bar; like a kick report, it is ignored after a jump back (the song position before where it was planned, or more wall time since then than song time). TAP and STRIP with ROLE KICK, PERC or DECK don't take part (SF KICK, PERC, STRIKE and DECK have no Pocket).

## ALLOC (mix assigner) [redesigned Nov 3]
Ten fixed bands (20-60, 60-100, 100-150, 150-220, 220-320, 320-480, 480-750, 750-1500, 1.5k-4k, 4k-20k Hz). Every instrument, SF STRIP, SF TAP and SF DECK measures its energy per band (40 ms attack, 80 ms release; the mean of both channels' energies, so wide and out-of-phase stereo counts) and publishes it; SF ALLOC decides cuts; each source applies its own cuts (bell EQ per band, gliding at 60 dB/s). The audio never leaves its track.
- A global order of sources (drag in SF ALLOC's list; top = most important), saved with the set, changed only by dragging. The order holds plugin instances, not names [Nov 3, second audit]: every SF plugin has an id saved with the set, so a source keeps its place when the set reopens (whatever order the plugins start in), when its track is renamed and next to sources of the same name (it used to go by name, and two PERCs listed as PERC / PERC 2 by start-up order could swap). A duplicated track's copy takes a new id and joins the end. Orders from older sets (names) are taken over on first sight. Any band can have its own order instead [decided Nov 3: different frequencies want different priorities]: click the band, drag (band marked OWN); LINK TO ALL returns it to the global order. Newcomers join the end of every order. Names: Live's track name (VST3 passes it; AU does not), else the module/role name; duplicates get " 2", " 3".
- Per band, a priority curve over the order: PRIORITY = position of the peak (0 top .. 100 % bottom), DEPTH = how hard sources away from the peak are cut (x MAX CUT; 0 = untouched), Q = width (Gaussian, sigma 3 rows at 0 .. 0.3 rows at 100 %). cut_i = MAX CUT x DEPTH x (1 - weight_i).
- MODE DYNAMIC (default): cut_i is scaled by how loudly the most active more-favoured source is playing in that band (above the SENSITIVITY floor, full at +18 dB). STATIC: always cut.
- Display: list left; per band a column with one lane per source (white = what plays, amber = what is cut), the curve (grey; cyan while its knob is touched), the owning source's name, and PRIORITY / DEPTH / Q knobs drawn in the column. The 30 band knobs are hidden from the generic grid but automatable.
- Replaces the conflict-slot design (Nov 2), which was unpredictable: hidden role priority, load-order ties, and knobs that rebound to whichever conflict was worst.

# Modules

## Instruments (MIDI tracks)
Mono models (BASS, ACID, MONO, MS20, HOOVER, SYNC): DENSITY echoes never interrupt a note that is still held; they fill the gaps between notes.

Every instrument has a MODEL menu (header), a SAMPLE model (drop a file or LOAD; embedded in the set as FLAC), DENSITY echoes, GATE, bipolar FILTER, ALLOC participation (ALLOC toggle), a LEVEL, and KEY FOLLOW (follows SF CONTROL's KEY; on by default) [Nov 3]. Every model is calibrated to the role's loudness target (Gain staging).

DENSITY (instruments): fills a sparse pattern with ghost notes. 0-50 %: one echo one ECHO SPACE later fades in (1/8 hats become 1/16 hats with ECHO SPACE 1/16). 50-100 %: two more ghosts at half spacing (1/32 rolls). Each generation is quieter, darker and shorter. ECHO SWING, ECHO PROB where useful. A ghost carries two levels [Nov 3, second audit]: its velocity (played softer: the instrument's velocity response, so no accents) and its DENSITY fade, applied after the velocity response, so a ghost really rises from silence (at 1 % of the knob it is 30 dB down; the velocity floors used to make it nearly full level). A quiet ghost (fade under half) doesn't cut the ringing kick or CHOKE the previous hit.

GATE (instruments): 0 = clipped staccato, 50 % = as played, 100 % = held long (release up to 8x).

### SF KICK
Models: KICK 909-TYPE, KICK 808-TYPE, KICK SINE, KICK INDUSTRIAL, KICK MODULAR, KICK DUB, SAMPLE. Row: TUNE, DECAY, PUNCH (pitch-sweep depth), CLICK, DRIVE, FILTER, DENSITY, LEVEL. Also: LAYER MODEL + LAYER (blend a second model, e.g. 909 click on an 808 body), PITCH TIME, VEL SENS, ECHO SPACE/SWING, KEY TRACK (off: any note plays the tuned kick), FILTER RES. Reports every hit (including echoes) to the bus. A sampled kick reports its analysed pitch and decay. On SAMPLE, DECAY is a gate: 10 ms at 0, the whole sample from 90 % up, exponential between, 8 ms fade. [decided Nov 2] Synthesis runs at 2x. With KEY on, the model's fundamental lands on the nearest key root and TUNE moves from there (TUNE 0 = on the root). [Nov 3]

### SF PERC
Models: HAT 909-TYPE, HAT 808-TYPE, HAT 606-TYPE, RIDE 909-TYPE, CRASH, CLAP, RIM, COWBELL, CLAVE, SHAKER, METAL FM, MODAL, SAMPLE. All synthesised (909 hats were samples in the original; these are approximations — load your own into SAMPLE for the real thing). Row: TUNE, DECAY, TONE (model brightness / ratios), DENSITY, FILTER, ACCENT (velocity depth), DRIVE, LEVEL. Also ECHO SPACE/SWING/PROB, CHOKE, SPREAD (echoes alternate left/right). On SAMPLE, DECAY gates the sample exactly as on SF KICK.

### SF RUMBLE
Kick-driven low-end bed. Listens to SF KICK on the bus (SOURCE: KICK BUS / MIDI / BOTH), excites a thump using the kick's own pitch sweep, through a model: REVERB, DELAY, SUB DRONE, DISTORTED, DUB BOOM, SAMPLE. Row: SIZE, DARK, GRIT, PUMP (pocket depth), GATE (tail cut-off after each kick), DENSITY (extra thumps between kicks), FILTER, LEVEL. Ducks around the kick with Pocket.

### SF BASS / SF LEAD / SF PAD
One synth engine, role-specific models and defaults. Row: CUTOFF, RES, ENV AMT, GATE, DENSITY, FILTER, DRIVE, LEVEL. Also DECAY, ATTACK, ACCENT, GLIDE (portamento), TUNE, DETUNE, COLOR (model-specific: sub level, osc 2 shape, drawbars, FM index, wavetable position, grain size, saw/square for acid), LAYER MODEL + LAYER, CHORD (MODEL default or MIN7 / MIN9 / SUS4 / MAJ7 / MIN / 5TH / OCT / NONE), SPACE (ensemble), POCKET DEPTH / SHAPE, ECHO SPACE / SWING.
- BASS models: BASS LADDER, MONO 101-TYPE, SUB OSC, ACID 303-TYPE, FM, SINE SUB, OFFBEAT, SAMPLE.
- LEAD models: ACID 303-TYPE, MONO 101-TYPE, MS20-TYPE, STAB DUB, STAB DETROIT, ORGAN M1-TYPE, HOOVER, FM BELL, SYNC, SAMPLE.
- PAD models: STRING MACHINE, POLY PAD, WAVETABLE, GRANULAR, DUB WASH, TAPE LOOP, NOISE BED, SAMPLE.
- ACID 303-TYPE: mono, 4-pole resonant ladder, accent from velocity > 108 (sharper, louder, shorter filter envelope; ACCENT sets how much), slide when notes overlap (legato, no retrigger). COLOR < 50 % saw, >= 50 % square.
- Mono models keep a note stack: releasing a note slides back to the one still held. A poly layer under a mono model releases its own voices when the mono layer slides (they used to stick). TUNE and KEY reach notes already sounding.
- SAMPLE: chromatic from the analysed root note. GRANULAR uses the loaded sample (or a built-in chord bed).
- Changing MODEL releases all voices.

### SF VOICE
Spoken-word / vocal phrases. A loaded phrase is sliced (SLICE MODE: AUTO onsets / EQUAL 8 / EQUAL 16 / WHOLE); C3 plays slice 1, C#3 slice 2 ...; keys below C3 play the whole phrase. Models: SAMPLE, RADIO (CB-style band-limit and dirt), VOCODER (16 bands, saw carrier at TONE pitch), ROBOT (pulse carrier, 8 kHz / 8-bit), CHOIR (vocoder with a minor-chord carrier), STUTTER (loops the start of the slice; TONE = loop length). Row: SIGNAL (clarity / sibilance), TONE, GATE, DENSITY, FILTER, ECHO (built-in dub echo send, ECHO TIME / ECHO FDBK), DRIVE, LEVEL. With no phrase loaded it plays a formant choir (TONE morphs A-E-I-O-U). drosaka Voice stays separate.

### SF STRIKE [added Nov 3]
Blast-excited resonant objects: industrial impacts, bells, sheet metal, distant detonations. Four voices ring at once: a fifth strike fades the quietest out over 5 ms (never cut); four more slots hold the fades. A pressure wave (Friedlander waveform: sharp overpressure, then a negative phase) from a charge of POWER at DISTANCE hits an OBJECT modelled as 6-16 resonant modes. The blast scales like the real thing: its duration grows with the cube root of the charge, its level falls with distance, and distance takes the highs away (air absorption). A short, close blast excites the high modes; a long, distant push the low ones. Big hits sound sharp for a moment and settle (TENSION). Above ~70 % POWER the object FRACTURES: modes split and detune, debris rattles, and the output saturates (2x oversampled; the amount follows the fractured voice's own envelope, smoothed, and fades in from clean, so nothing else ringing changes level).
- Objects: BELL, PLATE, BAR, TUBE, MEMBRANE, GONG (measured mode ratios).
- Row: POWER, DISTANCE, SIZE (pitch: bigger = lower), MATERIAL (wood to glass: how long the high modes ring), DECAY, DENSITY, FILTER, LEVEL. Also OBJECT, POSITION (strike point: mutes modes near a node), SPREAD (modes across the stereo field), TENSION, TUNE, KEY TRACK, FILTER RES, ECHO SPACE / SWING, VEL SENS (velocity scales the charge), ALLOC, KEY FOLLOW (the main partial lands on the nearest key root, TUNE moves from there; SIZE then picks the octave).
- Display: the blast's pressure-time curve for the current POWER / DISTANCE, and the object's modes.

### SF DECK
Two decks inside the set. Tracklist (drop files; persisted by path), background analysis on add/load: tempo + beat grid (onset regression, sample-accurate), integrated LUFS (BS.1770). Row: XFADE, FILTER A, FILTER B, LOW A, LOW B, ROLL, GATE (1/16 trance gate), LEVEL. Also PLAY A/B (start on the next QUANT boundary: 1 BEAT / 1 BAR / 4 / 8 / 16 BAR), MID/HIGH A/B (isolator: 0 = kill, 75 % = 0 dB, 100 % = +6 dB), KEY LOCK (Signalsmith Stretch, MIT licence; off = varispeed), CUE A/B (to the CUE output, pre-crossfader, for headphones), TRIM TARGET (every track normalised to this LUFS), FILTER RES.
- Decks always follow Live's tempo. A plugin cannot change Live's tempo; use Live's tempo automation for tempo transitions. [decided Nov 2]
- Hot cues from MIDI: C1-D#1 deck A cues 1-4, C2-D#2 deck B (jump on the next beat, short fade in; ignored while the deck is stopped). Default cues at beats 0 / 32 / 64 / 96.
- ROLL: slip loop roll (the track keeps running underneath; releasing returns to where it would have been). The rolled audio is read at tempo ratio, so with a large tempo difference it is slightly pitched (124 vs 128 BPM = about half a semitone).
- Loading a deck uses its own queue (never waits for list analysis) and reuses the list's analysis. Tracks are freed on the message thread, never on the audio thread.
- Transport jumps: playing decks keep running and are re-anchored by whole beats (stay on Live's grid). Beat grids are cached in seconds, so a sample-rate change keeps them valid. [decided Nov 2]
- Track log: every deck start is appended to Documents/SF Live Suite/tracklog.txt.
- Stems: use Live's stem separation, stems on their own tracks with SF TAP. [decided Nov 2]

### SF CONTROL
On its own MIDI track receiving the OXI One. MACRO 1-6 (published to every SF plugin), SONG (01-16), STORE ALL, PC CHANNEL (default 16), PC ENABLE, POCKET OFFSET, KEY (OFF, C ... B; per song) and PANIC (hold: every SF plugin fades out and clears) [Nov 3], STORE TO (ACTIVE SONG, SONG 01-16: where STORE ALL stores, without recalling it) [Nov 3, third review]. - SF TERROIR [Nov 4]: convolution reverb for real places. SIZE, DECAY, DARK, PREDELAY, DUCK, FREEZE, THROW, MIX (SF REVERB's first eight: the same ids in the same places, so it swaps in for SF REVERB on B SPACE and the E16 addresses fit; layout.py ALTERNATES, check_set.py and E16Map.h accept it there). Also PLACE (slot 1-8, in songs, not in presets), LENGTH (FULL, 4 BAR-1/16), REVERSE, START (0-250 ms), WIDTH (0-200 %), LO CUT, DUCK SHAPE, INPUT, DRY.
  - Slots: each a capture stored in the set as FLAC (24-bit, its own rate), with name, kind, RT60 and range over the noise; an empty slot plays a built-in synthetic room (1.8 s, RT 1.1 s, no direct sound). Drop files on the plugin: one file to the selected slot (more to the following slots); two files named ... L / ... R (LEFT / RIGHT, any separator) make one stereo place. A field recorder's poly file: the track names from its iXML TRACK_LIST (by INTERLEAVE_INDEX), else the sTRKn= lines of its bext description; tracks named MIX... (a MixPre writes MixL, MixR ahead of the inputs) are skipped when there are others, then the first two (one: a mono place); unnamed, the first two. Read in 64k-sample blocks, only the tracks used kept. Two channels carrying the same signal (difference 60 dB under it) make a mono place, its tail spread like any mono capture. Imports run on the module's worker thread; the status line reports the result (amber under 30 dB over the noise, red on a failure).
  - Captures (Source/core/IrTools): a recording holding the sweep is deconvolved (regularised spectral division, 30 Hz-18 kHz), every sweep found (spikes 40 dB over the median), the playback clock's drift fitted from their spacing and the reference regenerated at that pace (40 ppm measured to 0.1 ppm in the test), the responses averaged at their exact (fractional) positions, the speaker's harmonics left before them. Anything else is an impulse: the loudest event, from 1 ms before its onset (30 dB under the peak) to where the smoothed 10 ms decay comes within 5 dB of the noise floor (the median of the last quarter when it is flat; none when it is still falling), cut before a second event (12 dB over the lowest level since). Then a 1 ms fade in, a fade out over the last quarter (10-400 ms), a 20 Hz high-pass, and every place scaled to the same energy (0.85 per channel on average: SF REVERB's wet level within 1 dB on a held chord). Stereo is handled as one: the onset, the second-event cut, the noise floor and the sweep positions come from both channels together and one gain scales both, so a spaced pair keeps its time and level difference. The sweep file: 1 s of silence, then three 10 s exponential sweeps 20 Hz-20 kHz with 4 s gaps, -6 dBFS, 48 kHz mono, written to Music/SF Live Suite/TERROIR (SWEEP FILE on the display). Recordings up to 90 s, at 44.1 kHz or more for sweeps; an IR is at most 12 s.
  - Rebuilds: SIZE (resampled, the host rate in the same pass, 1/sqrt(SIZE) to hold the level), DECAY (an exponential envelope: RT60 x DECAY from the slot's measured RT60), DARK (a low-pass falling 8 x DARK^2 octaves a second from 20 kHz to 150 Hz), START, LENGTH (raised-cosine end, 15 % of it, 5-60 ms) and REVERSE (after LENGTH) make a new IR, at most 16 s, built on the worker thread (at most every 40 ms while a knob moves; in Live's offline render, in place at most every 2048 samples, so a render is the same every time) and handed to the engine; an IR built for another sample rate is never used.
  - Engine (Source/core/Convolver): uniformly partitioned overlap-save in two levels, mono in (the sum, after LO CUT, the input gain and PREDELAY), stereo out. Head: taps 0-4095 in 512-sample blocks, latency 512 = Pocket::kLatency (the module's latency; the Pocket then shapes the wet signal without delaying it). Tail: 4096-sample blocks on the input 512 samples late, partition 0 at the block line, the rest spread over the block before. A new IR keeps the input history (the input spectra don't depend on the IR): both are computed for one tail block and crossfaded (raised cosine, 4096 samples), so a tail is never cut. Same sums in the same order at any chunk size: bit-identical at every block size (SFTests). Direct convolution against it: -133 dB.
  - FREEZE: the wet signal's spectrum (two 8192-sample Hann frames, mean power) held and played as random-phase frames at 75 % overlap (4/3 amplitude: the captured level, measured 0.0 dB after 4 s), in over 150 ms, out over 400 ms; the input fades out (like SF REVERB) and the real tail dies under it.
  - Tests: SFTests --terroir (engine exactness and swaps; a sweep through a 1.2 s room with a 40 ppm clock and -70 dB noise; a clap with a second clap; DECAY, SIZE, LENGTH, REVERSE on the response; FREEZE level; a file dropped on the plugin, stored and reloaded; repeatable offline renders; level against SF REVERB; a MixPre-style poly file named in bext and in iXML, its pair used with 1.5 ms and 3 dB between the channels kept, a mono take saved as stereo stored mono). ## Master / mix
- SF ISOLATOR: LOW, MID, HIGH (0 = kill, 75 % = 0 dB, 100 % = +6 dB), LOW/MID/HIGH KILL, XOVER LO, XOVER HI. Linkwitz-Riley, phase-aligned.
- SF BUILD: BUILD (one knob: high-pass sweep to HP MAX, noise riser, reverb wash, width), DROP (hold: the drop lands on the next bar line; the build stays off until BUILD is turned below 5 %), NOISE, SPACE, WIDTH, HP MAX, LEVEL, GAP, TAIL, DROP DUCK, DUCK TIME [the last four: Nov 3, third review]. GAP (OFF, 1/16 to 1 BAR): everything through BUILD is silent for that long before the bar line (3 ms fade out, back in 0.25 ms on the bar); pressed later, the gap starts on the next 1/16. The build stops where the gap starts (on the bar without one). TAIL (CUT = 5 ms, 1/16 to 2 BARS): the riser's noise and the wash ring on from there, fading (raised cosine), with their colour and width frozen and no new input into the wash; longer than the gap, the tail runs into the drop DROP DUCK dB lower. DROP DUCK (0-12 dB, default 6) and DUCK TIME (1/4 to 4 BARS, default 1 BAR): the Pocket stages' drop duck (POCKET). A jump back while a drop waits (an Arrangement loop wrapped, a relocate) lands it at once, on the bar line a loop wraps to: in a loop with no bar line inside, the planned bar never came and a gap under way stayed silent. Display: DROP ON BAR / GAP (green), RETURN KNOB (amber).
- SF GLUE: PUSH (one knob: threshold + makeup), ATTACK, RELEASE (incl. AUTO dual-stage), RATIO, SC HPF, MIX, LEVEL. 6 dB soft knee [Nov 3]. Gain-reduction trace.
- SF TONE [added Nov 3]: master voicing EQ, five broad moves on one row: LOW (shelf at 70 Hz, +/-6 dB), MUD (cut at 280 Hz, 0-6 dB), PRESENCE (3.2 kHz, +/-4 dB), AIR (shelf at 12 kHz, +/-6 dB), TILT (+/-3 dB around 900 Hz), LEVEL. Runs at 2x so the air shelf keeps its analog shape up to 20 kHz. Gentle by design: the ranges stop before damage.
- SF LOWEND: MONO FREQ (mono below), SUB CLIP (2x oversampled), RUMBLE CUT (24 dB/oct), WIDTH (above), LOW TRIM, LEVEL.
- SF LIMIT [rebuilt Nov 3]: TARGET (LUFS), CEILING (dBTP), CLIP, INPUT, RELEASE, AUTO (moves the input, +/-12 dB, down at <= 1 dB/s and up at <= 0.5 dB/s, so the loudest short-term loudness of the last minute sits at TARGET; up only after 3 s of music within 6 dB of TARGET, so a breakdown is held and the drop comes back where it was), AUTO MODE (DOWN ONLY, default: never lifts above unity; UP AND DOWN: also lifts a quieter set) [Nov 3, second audit], RESET. Chain: INPUT (+ AUTO) > soft-knee CLIP at 4x through linear-phase FIR oversampling > true-peak lookahead limiter > CEILING. Detection: 8x true peak (32-tap windowed sinc) of the clipped signal. Gain: minimum over a 2 ms lookahead, program-dependent release (fast at RELEASE, held by a slow envelope under sustained limiting: no pumping on dense material, quick recovery after a lone peak), then a 2 ms moving average that always reaches each peak's gain before the peak leaves the delay line. Output true peak never exceeds CEILING (measured). Latency 176 samples at 48 kHz (reported to Live). AUTO measures the raw input, so the trim it needs is known directly and followed at <= 1 dB/s: no loop around the 3 s meter, no overshoot. Display: momentary, short-term, integrated (BS.1770-4 gated), true peak, GR, auto input.
- SF ROOM EQ: six cut-only bands (CUT 1-6, FREQ 1-6, shared Q), VENUE (1-16) recalls stored venues, STORE VENUE. Not part of songs.
- SF ALLOC: ENABLE, MODE, MAX CUT, SENSITIVITY, and PRIORITY / DEPTH / Q for each of the 10 bands (in the window). See ALLOC above.
- SF TAP: ROLE, ALLOC, POCKET DEPTH, POCKET SHAPE, LEVEL. Makes no sound of its own; puts any track into Pocket and ALLOC.
